信息架构：首页、分类、产品的三层结构模板

你熟悉的是公司，买家熟悉的是他自己的问题。

Felix　B2B 出海营销顾问

一句话答案 / TL;DR

B2B 独立站的信息架构用三层就够用：首页（我是谁、为什么信我、带我去哪）→ 分类页（按买家思维分组，不按公司内部分组）→ 产品页（参数 + 证据 + 询盘）。判断架构好坏只有一个标准：第一次来的买家能否在 3 次点击内找到任何他想看的东西，并在每一层都知道下一步该点什么。红线是按「关于我们 / 新闻中心 / 产品中心」这种公司内部视角组织导航。

三层各自的任务

首页不是百科，是分流器。首屏说清「你是谁、给谁服务、凭什么信」，第二屏给通往分类的入口，第三屏给信任证据（案例、证书、客户），全程不超过五屏。首页的任务是让买家在 30 秒内确定「来对地方了」，然后把他递送到正确的分类页——把首页做成「什么都有」的兜底页，等于没有首页。

分类页是 B2B 站被低估的枢纽。按什么分组是架构的灵魂：按买家行业（医疗 / 汽车 / 消费电子）分组，或按工艺与能力分组（CNC / 钣金 / 注塑）——选择标准是哪一种是买家找供应商时的真实思路。分类页要承担「解释这个类别 + 筛选具体产品」两个任务，只放产品缩略图的分类页，是浪费了 SEO 和转化的双重机会。

产品页是终端转化页。参数表、能力边界、相关案例、FAQ、询盘表单——结构固定。产品页本身怎么写，我在 《B2B 产品页 SEO 模板：改过 200 个产品页后的写法》里拆过。

导航设计的两个原则

第一，导航词汇用买家的词。导航里的「解决方案」在 B2B 里往往太虚——改成「按行业」或「按工艺」，或者直接写买家搜的词。检查方法：把导航词翻译成英文搜一遍，有搜索量说明买家真的这么叫；零搜索量的内部术语，从导航里撤掉。

第二，点击深度控制在三层。从首页到任何一个产品页，点击不超过 3 次。超过三层的站（产品藏在四级分类下），要么扁平化分类，要么用站内搜索和面包屑补位——但更根本的解法是把分类体系本身做浅：B2B 产品线再复杂，两层分类也装得下，装不下通常是分组逻辑错了。

架构和 SEO 的互相成全

三层结构恰好对应 SEO 的词库分层：首页卡品牌词，分类页卡类别买手词（比如 medical device components），产品页卡具体产品词。架构做对了，SEO 的页面规划就是顺水推舟；架构错了（比如所有产品堆在一个「产品中心」平铺列表下），SEO 就要替架构还债——用内链硬造层级，事倍功半。

架构阶段就引入 SEO 视角的另一个收益：URL 结构随架构一次定型（/capabilities/cnc-machining/ 这种语义化路径），后期改版不用动 URL——URL 稳定是排名资产。改版时怎么保住 URL 映射，我在那篇 GSC 未收录急救里讲过。

常见问题

产品很多（几百个 SKU）站不住三层怎么办？

层数不变，变的是分类逻辑：两层分类（能力 × 行业）交叉放不下的产品，用「系列」做产品页的聚合变体——/cnc-machining/aluminum-parts/ 一个页面挂多个规格变体，而不是每个规格一个页面。几百个 SKU 真正需要独立页面的可能只有几十个，其余用变体、筛选器、参数表解决。

多语言站架构要重新设计吗？

不重新设计，复制结构再本地化分组逻辑——德国买家找供应商的思路和美国人未必一样，比如对认证的分组权重更高；分类名称和顺序可以按市场调整，但三层骨架保留。骨架统一保证 hreflang 能一一对应，内容本地化交给各市场的词库。多语言站该用目录还是子域名，我在 《多语言独立站 SEO：hreflang 与翻译质量怎么选》里讲过。

导航里要不要放博客？

放一个「资源 / Insights」入口足够，不必给每篇博客导航位置。博客的价值在于承接搜索流量和内链，不是导航分流——导航位置给分类页和产品体系，这是流量资产的主航道。

老站架构乱了，怎么评估改不改？

看两个数据：GSC 里的抓取深度分布（大量重要页面在 4 层以下），以及站内搜索的热门查询（买家找不到才会搜站内）。两个都超标，重构进计划；都不超标，修修补补即可——架构重构牵动 URL，成本不小。
